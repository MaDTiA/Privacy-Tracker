What it is

A self-hosted BitTorrent tracker written in Python. It speaks the UDP tracker protocol (BEP 15), keeps track of peers for any info-hash, and exposes a small web interface for stats and torrent search: all without logging a single client IP address.

Why it exists

Public trackers log announce requests, revealing which torrents your peers are downloading. Privacy Tracker gives you a tracker you control, on your own server, that never persists IP addresses to disk: making it suitable for privacy-conscious communities and private trackers.

Use cases

  • Private torrent community or closed group tracker
  • Self-hosted fallback tracker in your magnet links
  • Developer tool: test BitTorrent clients locally
  • Research: monitor swarm sizes for specific torrents without relying on third-party trackers
  • Add a known-good tracker to your magnet URI as a reliability layer

Stack & architecture

Python 3 Flask UDP sockets threading systemd IPv4 + IPv6 BTDigg API ITorrents

Single .py file. The script embeds both the UDP tracker daemon and the Flask web app. Designed for a 1-core VPS: low memory footprint, no database required. Peer data is persisted as JSON on disk.

Quick start & deployment

# 1. Install dependencies pip install flask markupsafe werkzeug # 2. Create /opt/tracker/config.json with your password, port, admin path # 3. Run directly (dev) python tracker_v15_final.py # 4. Or as a systemd service (recommended for production) sudo systemctl enable --now tracker # 5. Add your tracker to a magnet link # udp://yourdomain.com:PORT/announce # 6. Access the web UI https://yourdomain.com/stats # public stats + search https://yourdomain.com/ADMINPATH # admin panel

The script auto-generates tracker.py (the optimised inner daemon) and launches the web layer alongside it. Both processes are managed by a single systemd unit with Restart=always. The auto-restart feature (configurable interval) lets you schedule periodic restarts from the admin panel without touching the server.

Circuit Breaker for external services New
New CB class wraps ITorrents and BTDigg: opens after 3 consecutive failures, self-heals after a configurable window.

The new CB (Circuit Breaker) class prevents the tracker from hammering a dead upstream. Once a service fails 3 times in a row, the circuit opens and calls are skipped immediately: no threads hanging, no timeouts stacking up in the worker pool.

  • cbit = CB("ITorrents", threshold=3, resetsecs=120): resets every 2 minutes.
  • cbbt = CB("BTDigg", threshold=3, resetsecs=300): resets every 5 minutes.
  • Thread-safe: uses an internal threading.Lock.
  • Self-healing: after the reset window the circuit closes automatically on the next successful call (cb.ok()).

Non-blocking external HTTP via Thread Pool New Perf
All outbound HTTP now runs in a dedicated ThreadPoolExecutor (4 workers) with a hard 10 s wall-clock deadline: Flask worker threads are never blocked by slow upstreams.

In v14, BTDigg and ITorrents calls ran inline inside Flask route handlers. If the upstream was slow or unresponsive, the entire worker thread blocked for up to 15 s, stalling all other concurrent requests.

v15 offloads every external call to a separate pool:

  • extpool = ThreadPoolExecutor(max_workers=4, thread_name_prefix="ext"): capped at 4 to avoid CPU saturation on single-core VPS.
  • Each call is submitted as a Future and awaited with future.result(timeout=10).
  • If the deadline is exceeded, FutureTimeoutError is caught, the circuit breaker is incremented, and an empty result is returned gracefully without crashing the route.
web layer: extpool + btdigsearch wrapper
+ extpool = ThreadPoolExecutor(max_workers=4, thread_name_prefix="ext") + def btdigsearch(query, limit=10): + if cbbt.isopen(): return [] + try: + fut = extpool.submit(btdigsearchinner, query, limit) + res = fut.result(timeout=10) + cbbt.ok() + return res + except FutureTimeoutError: + cbbt.fail() + return []
BTDigg: timeout 15 s → 8 s, buffer 512 KB → 256 KB Perf
Socket timeout halved; response read limit halved. Reduces worst-case latency and bandwidth on slow upstreams.

BTDigg's result markup appears in the first ~100 KB of its HTML response. Reading 512 KB was wasteful both in bandwidth and parse time. Combined with the new 10 s wall-clock cap from extpool, worst-case user-visible BTDigg latency drops from ~15 s → ~10 s.

Homepage: hard meta-refresh → 3-shot JS refresh Changed Fix
Page no longer reloads unconditionally every 15 s. A JS session counter stops after 3 auto-reloads; any user interaction cancels the next one immediately.

v14 used <meta http-equiv="refresh" content="15">: a jarring full-page reload every 15 s that interrupted users who were reading stats or clicking links.

v15 replaces it with a lightweight JS pattern using sessionStorage:

  • A counter tracks how many auto-reloads have fired in this browser session.
  • After 3 reloads (MAX=3, interval 15 s) the timer stops for the rest of the session.
  • Any keydown or mousedown event before the timer fires cancels the reload entirely.
homepage: refresh strategy
- <meta http-equiv="refresh" content="15"> + <script> + var MAX=3, IV=15000, F="arf", C="arc"; + var cnt = was ? parseInt(sessionStorage.getItem(C)||0, 10) : 0; + if(cnt < MAX) { + var tid = setTimeout(function(){ sessionStorage.setItem(F,1); + sessionStorage.setItem(C, String(cnt+1)); location.reload(); }, IV); + function cancel(){ clearTimeout(tid); } + document.addEventListener("keydown", cancel, {once:true}); + document.addEventListener("mousedown", cancel, {once:true}); + } + </script>
Stats page: infinite setInterval → 3-shot refresh Changed
The live torrent list no longer polls /api/stats every 30 s indefinitely: same 3-shot session-counter pattern caps background API traffic.

First Public Release: Baseline
The foundation from which all future changes are tracked.

This is the initial baseline: no prior public changelog exists. Key capabilities present in v14:

  • UDP BitTorrent tracker (BEP 15): IPv4 + optional IPv6, connection/announce/scrape, low-memory mode
  • Peer cleanup daemon + periodic stats persistence to stats.json
  • systemd auto-restart via os.exit(0) + Restart=always
  • Flask web layer: public stats page with live torrent list, unified search (local + BTDigg), hash resolution via ITorrents & BTDigg, legacy ?search= query param support
  • REST API: /api/stats, /api/torrent/<hash>, /api/search, /api/list, /api/resolve, /api/lookup, /api/name2hash
  • Admin panel: password login, API key management (per-key hourly rate limits), ad slot injection (5 slots), Google Analytics code injection, tracker-list editor, public-stats toggle
  • Brute-force login protection: 5 attempts → 15-minute lockout
  • Config & stats hot-reload with TTL cache (30 s / 10 s)
  • Homepage hard auto-refresh via <meta refresh="15">; stats torrent list polled every 30 s via setInterval
